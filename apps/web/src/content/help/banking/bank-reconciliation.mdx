Bank reconciliation checks that what Fintranzact has recorded agrees with what actually went through your bank. You upload the statement your bank gives you: CSV, Excel, OFX, QFX, QIF or PDF. Fintranzact reads every line and tries to match it to a payment, expense, or bank transaction you have already recorded. You then review the lines it could not match.

:::note
Bank Reconciliation is available in the web and desktop app only. The mobile app does not have it yet.
:::

## Opening Bank Reconciliation

In the sidebar, go to **Accounts → Bank Reconciliation**. The page is titled **Bank Reconciliation** and has six tabs:

| Tab | What it is for |
|---|---|
| **Reconciliation Hub** | Your bank accounts and a history of statement imports |
| **Upload & Map** | Upload a statement file and map its columns |
| **Review Matches** | Go through each statement line and confirm, match, or ignore it |
| **Summary (BRS)** | Compare the book balance with the statement balance for one account |
| **Rules** | Categorisation rules for recurring narrations |
| **Templates** | Saved column layouts for different banks |

### Who can use it

| Role | Access |
|---|---|
| Owner, Admin | Full access |
| Accountant | Full access: import statements, match lines, and manage rules and templates |
| Seller, Seller Manager | No access. The menu item is hidden. |

## Reconciliation Hub

The hub is the first tab you see when you open the page.

**Bank accounts** shows one card for each account you set up in [Cash & Bank](/help/banking). Cash accounts are left out, because cash has no bank statement. Each card shows the account name, bank name, account type, the last four digits of the account number, and the current balance. It has two buttons:

- **Import statement** opens the **Upload & Map** tab.
- **View BRS** opens the **Summary (BRS)** tab for that account.

If you have no bank accounts yet, the hub shows **Add bank account**, which takes you to **Cash & Bank**.

**Recent imports** lists every statement you have uploaded, newest first, 20 per page:

| Column | Meaning |
|---|---|
| **File** | The name of the file you uploaded |
| **Status** | `pending` (uploaded, but columns not confirmed yet) or `review` (lines parsed and matched) |
| **Lines** | Number of transaction lines read from the file |
| **Matched** | Lines that are auto-matched, manually matched, or turned into an expense |
| **Unmatched** | Lines still waiting for action |
| **Date** | When the import was created |

Click **Review** on a row to open that import in the **Review Matches** tab.

## Importing a bank statement

### Step 1: Upload the file

1. Open the **Upload & Map** tab, or click **Import statement** on the hub.
2. Choose the account under **Bank Account \***.
3. Drag the file onto the **Statement File \*** box, or click it to browse.
4. Click **Upload & Detect Columns**.

These formats are accepted:

| Format | Notes |
|---|---|
| **CSV** (`.csv`) | Read as it is. |
| **Excel** (`.xlsx`) | The first sheet is read. Title and account rows above the column headings are dropped. Old `.xls` files are not supported: save them as `.xlsx` or download CSV instead. |
| **OFX / QFX** (`.ofx`, `.qfx`) | Each transaction becomes a line with **Date**, **Description**, **Reference**, **Debit** and **Credit** columns. |
| **QIF** (`.qif`) | Bank, cash and card registers. Dates are read day first, like `01/04/2026` or `1/4'26`. |
| **PDF** (`.pdf`) | Text is read into columns from the heading row onward. If the PDF is password protected, enter its password when asked (banks often use your date of birth or customer ID). Scanned PDFs have no text and can't be read: download the Excel or CSV statement instead. |

Excel, OFX, QIF and PDF files are converted to CSV in your browser before upload, so the next step works the same for every format. The converted file can be up to about 10 MB. PDF reading is best effort, so check the preview on the mapping screen.

The CSV reader deals with the usual problems in Indian bank exports:

- A byte-order mark at the start of the file, and Windows line endings
- Quoted fields that contain commas or line breaks
- Blank rows, and separator rows made only of dashes, `=` or `*`

### Step 2: Check the column mapping

After the upload, the page shows **Map Columns** with the file name. Fintranzact fills in the mapping automatically in one of two ways:

- **Bank template detected.** If the file matches a built-in or saved template, a green **Detected** banner shows the bank name, template version, and match percentage. Click **Use Template** to import straight away with that template. Click **Manual Mapping** to hide the banner and set the columns yourself.
- **No template.** Fintranzact guesses each column from its header text. For example, `Narration`, `Description`, or `Particulars` becomes the narration. `Withdrawal Amt` or `Debit` becomes the debit column, and `Chq./Ref.No.` or `UTR` becomes the reference.

Check the mapping against the **Preview (first 5 rows)** table at the bottom. Each column is labelled with its position, for example `[4] Withdrawal Amt.`.

| Field | Required | Notes |
|---|---|---|
| **Apply a saved template (optional)** | No | Uses a template's layout and its row-cleaning rules. See Templates. |
| **Date Column \*** | Yes | Transaction date |
| **Narration Column \*** | Yes | Description or particulars |
| **Debit Column** | No | Withdrawals. Map this together with **Credit Column**. |
| **Credit Column** | No | Deposits. Map this together with **Debit Column**. |
| **Amount Column (if single col)** | No | Use this only when the statement has one amount column instead of separate debit and credit columns |
| **Type Column (DR/CR)** | No | Used with a single amount column. `DR`, `Debit`, or `Withdrawal` makes the line a debit; anything else makes it a credit. |
| **Reference / Cheque No Column** | No | Cheque number, UTR, or reference number. It is used for exact matching. |
| **Balance Column** | No | Running balance. The last line's balance becomes the statement's closing balance in the BRS. |
| **Date Format** | No | **DD/MM/YYYY (Indian standard)**, **MM/DD/YYYY**, **YYYY-MM-DD (ISO)**, or **DD-MMM-YYYY (01-Jan-2024)** |
| **Skip Rows (header rows)** | No | Number of rows at the top of the file to skip before the transactions start. The default is 1, which skips the header row. |

Some date layouts are recognised whatever format you pick: ISO dates (`2024-04-01`), `YYYYMMDD`, and month-name dates such as `01-Apr-2024` or `01 Apr 24`. For slash, dot, or dash dates like `01/04/2024`, the **Date Format** decides which part is the day and which is the month. Two-digit years are read as 2000–2049 or 1950–1999. Rows whose date cannot be read are skipped. Summary rows like "Opening Balance" at the top or bottom are dropped this way.

:::caution
Use separate **Debit Column** and **Credit Column** mappings whenever your statement has them. If you map a single **Amount Column** with no **Type Column**, every line is imported as a credit, even when the amount has a minus sign. If only one of Debit or Credit is mapped and no Amount column is set, every line imports with a zero amount.
:::

### Step 3: Confirm and auto-match

Click **Confirm & Auto-Match**. Fintranzact reads every row, matches each line (see How auto-matching works), and shows a message like "Parsed 142 lines. 118 auto-matched, 24 unmatched." Then it opens the **Review Matches** tab for this import.

To reuse this layout next time, click **Save as Template** before confirming. See Templates.

:::caution
Fintranzact does not check whether a statement has been imported before. If you upload the same statement twice, or two statements with overlapping dates, you get two separate imports with duplicate lines. The same payment or expense can then be auto-matched in both imports.
:::

## How auto-matching works

Auto-matching looks at your records dated from 7 days before the first statement line to 7 days after the last one:

- **Credit lines** (money in) are matched against payments and bank transactions.
- **Debit lines** (money out) are matched against expenses and bank transactions.

Amounts must be equal, with a tolerance of 1 paisa. Fintranzact tries four levels in order and takes the first record that fits. Each record can be matched to only one line per import.

| Confidence | Rule |
|---|---|
| **100%** | Same amount, same day, and the statement's reference number equals the record's reference number, ignoring case and spaces. For bank transactions, the reference is compared with the transaction description. |
| **90%** | Same amount, dates no more than 2 days apart |
| **80%** | Same amount, and a UPI ID, cheque number, NEFT/RTGS UTR, or IMPS reference found in the narration also appears in the payment's reference number, or in the expense's reference number or description. Dates are not checked at this level. |
| **70%** | Same amount, dates no more than 7 days apart. Payments and expenses only. |

The confidence appears in the **Confidence** column on the review screen. Any line that does not fit one of these levels is left **Unmatched**.

Fintranzact can read these narration formats:

| Type | Example narrations |
|---|---|
| UPI | `UPI/raj@okicici/RAJ TRADERS/...`, `UPI-...-raj@ybl` |
| Cheque | `CHQ NO 123456`, `CHEQUE NUMBER 123456`, `CQ NO 123456` (5–9 digits) |
| NEFT | `NEFT/<16–22 character UTR>/...`, `NEFT-CMS-.../<UTR>` |
| RTGS | `RTGS/<16–22 character UTR>/...` |
| IMPS | `IMPS/<10–20 character reference>/...` |

:::tip
Auto-matching works best when you enter the UTR, cheque number, or UPI transaction ID in the **Reference** field when you record a payment or expense.
:::

Keep in mind:

- Payments are matched on amount and date only, without looking at which bank account they were recorded against or whether they were received or paid out.
- Payments you made to suppliers are never compared with debit lines. Only expenses and bank transactions are.

Always review auto-matches before relying on them, especially the 70% ones.

## Reviewing matches

The **Review Matches** tab works on one import at a time. Open it from **Review** on the hub, or you land here automatically after an import. At the top, a strip shows the **File**, **Total Lines**, **Matched**, **Unmatched**, and the statement **Period** (the first to the last transaction date).

Filter the lines with the pills: **All Lines**, **Unmatched**, **Auto-Matched**, **Manual-Matched**, **Expense Created**, and **Ignored**. The table shows 20 lines per page, with columns **#**, **Date**, **Narration** (with the reference number under it), **Debit**, **Credit**, **Status**, **Confidence**, and **Actions**.

### Line statuses

| Status badge | Meaning | Actions available |
|---|---|---|
| **Auto-matched** | Fintranzact found a likely match | **Confirm**, **Reject** |
| **Manual** | You confirmed an auto-match or matched the line by hand | **Unmatch** |
| **Unmatched** | No match found yet | **Match**, **+ Expense** (debit lines only), **Ignore** |
| **Expense created** | You created a new expense from this line | None |
| **Ignored** | You chose not to reconcile this line | None |

- **Confirm** accepts an auto-match. The line becomes **Manual**.
- **Reject** and **Unmatch** ask "Are you sure you want to unmatch this line?" If you confirm, the line goes back to **Unmatched**.
- **Ignore** marks the line as ignored, for example an opening-balance row or a transfer between your own accounts that you don't want to reconcile. The review screen has no way to undo **Ignore**.

**Matched** counts lines that are auto-matched, manual, or expense created. Ignored lines count in neither **Matched** nor **Unmatched**.

### Matching a line by hand

Click **Match** on an unmatched line. A panel titled **Manual Match** opens with the amount, date, narration, and reference.

- For a **credit** line, choose a record under **Select Payment**. Each option shows the amount, date, and reference number.
- For a **debit** line, choose a record under **Select Expense**. Each option shows the amount, category, and date.

Click **Confirm Match**. The line becomes **Manual** at 100% confidence.

:::note
The picker lists only your 50 most recent payments or expenses, and does not filter them by amount or date. To match an older record, check whether the auto-match already found it. You can also record the transaction again, or create an expense from the line instead.
:::

### Creating an expense from a statement line

Bank charges, auto-debits, and small UPI spends often appear on the statement before they are entered in the books. For an unmatched **debit** line, click **+ Expense**. The **Create Expense** panel opens with:

- **Category \***. This is filled in from a matching categorisation rule, if one applies.
- **Description**. This is filled in from the narration.

Click **Create Expense**. Fintranzact creates the expense with the line's amount, date, and reference number, and sets its payment mode to **Bank**. The line becomes **Expense created**. Creating expenses this way needs permission to create expenses.

:::caution
An expense created from a statement line does not add a withdrawal to the bank account in **Cash & Bank**. The account's current balance, which is the BRS book balance, therefore stays the same. An expense recorded from the Expenses page does add a withdrawal. If you need the bank balance to reflect the charge, add a matching withdrawal with **+ Add Transaction** in [Cash & Bank](/help/banking).
:::

## Summary (BRS)

The **Summary (BRS)** tab shows a **Bank Reconciliation Statement** for one account. Pick the account under **Bank Account**, or click **View BRS** on the hub. The figures come from the **most recent import** for that account.

| Line | Where it comes from |
|---|---|
| **Book Balance (Ledger)** | The account's current balance in Cash & Bank, as of today |
| **Statement Balance** | The balance on the last line of the most recent import. It shows `—` if you did not map a **Balance Column**. |
| **Unmatched Debits (statement only)** | Total of debit lines still **Unmatched** in that import. Shown only when more than zero. |
| **Unmatched Credits (statement only)** | Total of credit lines still **Unmatched** in that import. Shown only when more than zero. |
| **Difference** | Statement Balance minus Book Balance. Shows **Reconciled ✓** when it is exactly zero. |

The unmatched totals are shown to help you explain the difference. They are not subtracted from it.

:::caution
- **Statement Balance** is read from the last row in the file. If your bank lists transactions newest first, the last row is the oldest one, so its balance is not your closing balance. Re-save the statement oldest first before importing.
- **Book Balance** is today's balance, not the balance on the statement's last date. Anything you recorded after the statement period, such as payments or expenses, will show up in the difference.
:::

## Categorisation rules

The **Rules** tab (**Categorization Rules**) holds patterns for bank narrations that repeat, such as a monthly SaaS charge or a regular food-delivery debit. Click **+ New Rule** and fill in:

| Field | Options |
|---|---|
| **Match Field** | **Narration** or **Reference No** |
| **Match Type** | **Contains**, **Starts With**, **Exact**, or **Regex** |
| **Match Value \*** | The text or pattern, for example `SWIGGY` or `UPI/.*@ybl`. Matching ignores upper and lower case. |
| **Action** | **Create Expense**, **Ignore**, or **Tag Party** |
| **Priority** | 0–100. When several rules match a line, the highest priority wins. |
| **Expense Category** | Shown only for **Create Expense** |

The rules table shows **Match**, **Pattern**, **Action**, **Category**, **Priority**, **Hits**, and **Status**, with **Edit** and **Delete** for each rule.

What rules do today:

- When a statement is imported, the highest-priority active rule that matches a line saves its **Expense Category** on that line. When you click **+ Expense** on the line, the **Category** is already filled in.
- Rules do **not** create expenses, ignore lines, or tag parties automatically, whatever the **Action** says. You still take those actions yourself on the **Review Matches** tab.
- Rules apply only to imports you confirm after creating them. Lines that were already imported are not updated.

:::note
The **Hits** column currently always shows 0. The app does not yet count how often a rule is used.
:::

## Templates

A template stores a column mapping for a bank's CSV layout, plus rules for skipping disclaimer, header, or subtotal rows. The **Templates** tab lists them with **Bank**, **Version**, **Type**, **Format**, **Label**, and **Status**. Use the page search to filter by bank name.

### Built-in templates

The first time you upload a statement, Fintranzact adds built-in templates for these banks:

State Bank of India, HDFC Bank, ICICI Bank, Axis Bank, Kotak Mahindra Bank, Punjab National Bank, Bank of Baroda, Union Bank of India, IDBI Bank, and IndusInd Bank.

Until you upload your first statement, the Templates tab is empty and says "Templates are seeded on first bank statement upload".

### How a template is detected

When you upload a file, Fintranzact scores each active template against it:

| Signal | Weight |
|---|---|
| The bank account's IFSC starts with the template's IFSC prefix | +40% |
| The account's **Bank Name** matches the template's bank | +30% |
| All of the template's expected header words are in the header row | +30% |
| The file has the expected number of columns | +10% |
| The bank's name or other expected text appears in the first few rows | +20% |

A template needs at least 50% to be suggested. If a bank has more than one version, Fintranzact tries the newest version first and falls back to older ones if the columns don't fit the data. Filling in **IFSC** and **Bank Name** on your bank account makes detection much more reliable.

### Types of template

| Type badge | Meaning | Actions |
|---|---|---|
| **Built-in** | Ships with Fintranzact. It cannot be edited or deleted. | **Fork** |
| **Forked** | A copy of another template, saved as the next version number for that bank | **Delete** |
| **Custom** | Created with **Save as Template** on the mapping screen | **Delete** |

**Fork** copies a template as a new version you own ("Template forked — you can now edit the copy"). The Templates tab has no editor. To use a different column layout, map the columns on the **Upload & Map** tab and click **Save as Template**. Enter **Bank Name \*** (for example `HDFC Bank`) and an optional **Label** (for example `Savings account format`), then click **Save Template**.

:::note
Custom templates saved from the mapping screen have no detection rules, so they are never detected automatically. Choose them yourself under **Apply a saved template (optional)**.
:::

<ForBusiness>
**A simple monthly routine**

1. At the start of each month, download last month's statement from net banking. CSV or Excel works best.
2. Import it and click **Use Template** if your bank is detected.
3. On the **Unmatched** filter, click **+ Expense** for bank charges, SMS charges, and similar debits. Use **Match** for any customer payments that were not picked up.
4. Check **Summary (BRS)**. If the difference is not zero, look for payments or expenses you have not recorded yet.
</ForBusiness>

<ForCA>
**Preparing a BRS for a client**

- Make sure the client's receipts and payments carry UTR or cheque numbers in the **Reference** field. This moves most lines into the 100% and 80% levels.
- Work through the 70% matches line by line. They match on amount and a 7-day window only, so two invoices for the same amount can be swapped.
- The on-screen BRS compares the statement closing balance with the current book balance. For a period-end BRS, compare the statement's closing balance with the book balance on that date (see the running **Balance** column in [Cash & Bank](/help/banking)). Use the **Unmatched Debits** and **Unmatched Credits** totals as your reconciling items.
</ForCA>

## Frequently asked questions

**Does Fintranzact connect to my bank directly?**
No. There is no live bank feed. You download the statement from your bank and import it on the **Upload & Map** tab.

**Can I import a PDF or Excel statement?**
Yes. The upload accepts `.xlsx` and PDF files as well as CSV, OFX, QFX and QIF. For PDFs, a CSV or Excel download from the same bank usually gives cleaner columns. Password-protected PDFs work; scanned PDFs don't.

**My bank is not in the built-in list. Can I still import?**
Yes. Map the columns yourself on the mapping screen, then click **Save as Template** so the layout is ready for next month.

**Why are all my lines showing as credits?**
You probably mapped a single **Amount Column** without a **Type Column**. Map the separate **Debit Column** and **Credit Column** instead, or add the **Type Column (DR/CR)**.

**The same payment was matched in two imports. Why?**
Each import is matched on its own, and Fintranzact does not detect duplicate or overlapping statements. **Reject** the extra match, or avoid importing overlapping periods.

**Can I undo "Ignore" or "Expense created"?**
Not from the review screen. **Unmatch** and **Reject** only work on auto-matched and manually matched lines. If you created an expense by mistake, delete it from the Expenses page.

**Why does the BRS show a difference even though every line is matched?**
The **Difference** compares the statement's closing balance with today's book balance. Transactions recorded after the statement period, expenses created from statement lines (which do not change the bank balance), and a wrong opening balance on the account all show up as a difference.

**Is bank reconciliation available on the mobile app?**
No. Use the web app or the desktop app.
