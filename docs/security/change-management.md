## What the pipeline enforces today

`.github/workflows/ci.yml` (names matter: branch protection refers to them, never rename):

| Check | What it does |
|---|---|
| Typecheck & Lint | `pnpm typecheck` (all packages), `oxlint --deny-warnings` |
| Test | `turbo test` for every package (shared, api, web, mobile, ...), with a real PostgreSQL 16 service |
| Build | Builds the packages |
| License Scan | `pnpm licenses:check`: production dependencies must not use denied licences (AGPL, GPL, SSPL, ...) |
| Docker Build (dry run) | Builds the root `Dockerfile` on pull requests |
| E2E Tests | Playwright journeys |
| Check Feature Parity | `parity-check.yml` / `scripts/check-parity.ts`: every tRPC procedure is covered or exempted in CLI/MCP parity |

`.github/workflows/security.yml` adds Dependency audit, Static analysis, Secret scan and Image scan ([vulnerability-management.md](vulnerability-management.md)). Not required yet; add them to branch protection after two green weeks.

Also: database migrations are generated by drizzle-kit and checked in (the team convention is to run `drizzle-kit check` for the unified, control and tenant configs before merging; CI does not run it); `docs/ROLLBACK.md` describes rollback. Releases are tagged by `scripts/release*.sh`, built by `release.yml`; web deploys by `deploy-web.yml`.

## Rules

1. All changes arrive as pull requests from a branch; `main` is never pushed to directly. A second person reviews anything touching authentication, permissions, encryption, payments, payroll or migrations [reviewer]; a solo maintainer reads their own diff the next day and records that.
2. Required checks must be green. If one is flaky, fix or quarantine it in its own pull request; do not merge red.
3. Dependabot pull requests get the same review. No auto-merge.
4. Migrations are additive where possible; destructive ones need a backup first and a note in the pull request ([backup-and-recovery.md](backup-and-recovery.md)).
5. Production secrets are changed in the host's configuration, never in the repo; a change to a secret is logged on the calendar sheet.
6. Emergency fix: branch, minimal change, tests that fail without it, merge with a second pair of eyes after the fact within 1 working day; record why in the pull request.
7. After each release: smoke test (sign in, create an invoice, open a report) and watch error logs for an hour.
